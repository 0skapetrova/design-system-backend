# Design System Backend

Серверная часть приложения для управления дизайн-проектами и спецификациями.  
Отвечает за авторизацию, работу с пользователями и доступ к данным через REST API.  
Проект написан на **Node.js + TypeScript**, использует **Express**, **PostgreSQL** и централизованную систему ошибок.

---

## 🧩 Основные возможности

- Возврат данных текущего пользователя (`GET /api/auth/me`)
- Проверка телефонного номера и подготовка к флоу регистрации
- Единый формат ошибок (`error`, `message`, `details`)
- Чёткая архитектура приложения:
  - маршруты → контроллеры → сервисы → репозитории
- Разделённая документация: API, база данных, окружение разработчика (`/docs`)

---

## 🚀 Быстрый старт

1. Установите зависимости:
   ```bash
   npm install
   ```

2. Создайте базу данных PostgreSQL и пользователя, которому разрешено подключение.

3. Создайте файл `.env` (можно скопировать из `.env.example`) и заполните параметры подключения к базе данных.

4. Выполните миграции из каталога `migrations`, чтобы создать необходимые таблицы.

5. Добавьте тестового пользователя для работы эндпойнта `/api/auth/me`:
   ```bash
   npm run seed:dev
   ```

6. Запустите сервер:
   ```bash
   npm run dev
   ```

Сервер по умолчанию доступен по адресу  
`http://localhost:3000` — порт можно изменить через переменную `PORT`.

---

## 🌱 Переменные окружения

Минимальный набор для работы приложения:

- `PGHOST` — адрес сервера PostgreSQL  
- `PGPORT` — порт (обычно `5432`)  
- `PGDATABASE` — имя базы  
- `PGUSER` — пользователь базы данных  
- `PGPASSWORD` — пароль  
- `PORT` — порт HTTP-сервера (необязательно)

## 🔌 API

Базовый путь всех методов: `/api`.

- **GET /api/ping**  
  Проверка доступности сервера. Возвращает `{ ok: true, ts }`.

- **POST /api/auth/request-code**  
  Принимает `{ "phone": "<digits>" }`, проверяет формат телефона и возвращает информацию о лимитах запросов SMS-кода.

- **GET /api/auth/me**  
  Возвращает публичный профиль текущего пользователя.  
  В дев-режиме используется пользователь с `DEV_USER_ID` — убедитесь, что он есть в базе (`npm run seed:dev`).

## 📁 Структура проекта

```
.
├── src/
│   ├── routes/          # маршруты API
│   ├── controllers/     # обработчики запросов
│   ├── services/        # бизнес-логика (auth, users)
│   ├── repositories/    # запросы к базе данных
│   ├── middlewares/     # логирование, ошибки, cors
│   ├── utils/           # вспомогательные функции
│   └── server.ts        # точка входа
│
├── migrations/          # SQL-миграции
├── scripts/             # служебные скрипты (включая сид dev-пользователя)
├── docs/                # документация по API, БД и dev-настройкам
└── package.json
```

---

## 📚 Документация

В каталоге `docs/` находятся:

- **api/** — описания всех эндпойнтов и примеры JSON  
- **db/** — структура таблиц, индексы, правила хранения данных  
- **dev/** — параметры окружения и рекомендации по интеграции с фронтендом  

Документация является источником истины — изменения в API и данных должны отражаться в `/docs` до внедрения в код.

---

## 🛠 Логирование и ошибки

- Все ошибки приводятся к единому формату JSON  
- Коды ошибок, статусы и сообщения централизованы в `src/utils/errors/errorCatalog.ts`  
- Обработка ошибок выполняется через `src/middlewares/errorMiddleware.ts`
